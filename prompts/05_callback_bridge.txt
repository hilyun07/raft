Target version/semantics:

* Use etcd-io/raft v3.7.0 semantics as the reference.
* `Storage` is the Go raft library interface supplied by the embedding application.
* The C-backed RawNode must be able to call that Go `Storage` through a safe C callback table.
* Do not replace the app’s Go Storage with a C storage implementation in this phase.
* Do not implement unrelated consensus logic in this phase.

Goal:

Complete the Go-backed Storage callback bridge so that C RawNode can call the app-provided Go `Storage` through `raft_storage_ops_t`.

Conceptual target:

```text
Go Config.Storage
  -> storageBridge{storage: Config.Storage}
  -> cgo.NewHandle(...)
  -> C raft_storage_ops_t {
       handle,
       initial_state,
       entries,
       term,
       first_index,
       last_index,
       snapshot,
     }
  -> C raft_raw_node_new(...)
```

When C core needs storage:

```text
C raft core
  -> rn->storage.entries(handle, lo, hi, max_size, out)
    -> exported Go bridge function
      -> cgo.Handle(handle).Value()
      -> Go Storage.Entries(lo, hi, maxSize)
      -> C-owned deep copy of returned entries
      -> return C error code
```

Required C Storage ABI:

Use the repository’s existing naming if it already exists. If names differ, keep the repository’s convention but enforce the following semantics.

The storage ops must contain:

* an opaque integer handle, not a raw Go pointer,
* callbacks for all Go `Storage` interface methods:

  * `InitialState`
  * `Entries`
  * `Term`
  * `FirstIndex`
  * `LastIndex`
  * `Snapshot`

Preferred shape:

```c
typedef struct raft_storage_ops {
    uintptr_t handle;

    int (*initial_state)(uintptr_t handle,
                         raft_hard_state_t *hs,
                         raft_conf_state_t *cs);

    int (*entries)(uintptr_t handle,
                   uint64_t lo,
                   uint64_t hi,
                   uint64_t max_size,
                   raft_entry_array_t *out);

    int (*term)(uintptr_t handle,
                uint64_t index,
                uint64_t *out_term);

    int (*first_index)(uintptr_t handle,
                       uint64_t *out_index);

    int (*last_index)(uintptr_t handle,
                      uint64_t *out_index);

    int (*snapshot)(uintptr_t handle,
                    raft_snapshot_t *out);
} raft_storage_ops_t;
```

If the repo currently uses `void *user_data`, replace it with `uintptr_t handle` unless there is a documented reason not to. C must not store a raw Go pointer.

Handle/lifecycle requirements:

The C-backed Go `RawNode` must store the storage handle so it stays alive for the lifetime of the C RawNode.

Preferred Go shape:

```go
type storageBridge struct {
    storage Storage
}

type RawNode struct {
    p *C.raft_raw_node_t

    id     uint64
    logger Logger

    storageHandle cgo.Handle
    loggerHandle  cgo.Handle // only if actually used
}
```

Rules:

* Create the storage handle before `C.raft_raw_node_new`.
* If `C.raft_raw_node_new` fails, delete the handle before returning.
* Do not delete the handle while C can still call storage callbacks.
* Ensure there is a clear destroy/finalizer lifecycle for the C-backed RawNode.
* If the Go public API has no explicit RawNode destroy method, document the current lifecycle limitation and use the repository’s chosen cleanup pattern. If a finalizer is added, it must destroy the C RawNode before deleting the handle.
* Do not rely on finalizers for deterministic correctness in tests that explicitly need cleanup; provide an internal test helper if needed.

Panic safety:

Every exported Go storage bridge function must recover panics and return a C error code.

Pattern:

```go
func bridge(...) (rc C.int) {
    defer func() {
        if r := recover(); r != nil {
            rc = C.RAFT_ERR_PANIC_FROM_GO_CALLBACK
        }
    }()

    ...
}
```

Do not let a Go panic cross into C.

Error mapping requirements:

Use the repository’s documented C error enum and Go error mapping.

Map Go storage errors precisely:

* compacted error -> `RAFT_ERR_STORAGE_COMPACTED`
* unavailable error -> `RAFT_ERR_STORAGE_UNAVAILABLE`
* snapshot temporarily unavailable -> `RAFT_ERR_SNAPSHOT_TEMPORARILY_UNAVAILABLE`
* nil/invalid argument -> `RAFT_ERR_INVALID_ARGUMENT`
* allocation failure -> `RAFT_ERR_OUT_OF_MEMORY`
* callback panic -> `RAFT_ERR_PANIC_FROM_GO_CALLBACK`
* unknown storage error -> existing generic storage/fatal error code, according to `ERROR_MAPPING_FOR_C_PORT.md`

Do not collapse all storage errors into one generic error if the docs require distinct mapping.

Ownership and deep-copy requirements:

Scalar callbacks:

* `Term`
* `FirstIndex`
* `LastIndex`

These only write scalar output values.

`InitialState`:

* Convert Go `HardState` into `raft_hard_state_t`.
* Convert Go `ConfState` into `raft_conf_state_t`.
* If `raft_conf_state_t` contains arrays, allocate C-owned arrays and copy voters/learners/voters_outgoing/learners_next.
* The C side must have a documented free function for any allocated ConfState contents, or the owning aggregate free function must release them.

`Entries`:

* Call Go `Storage.Entries(lo, hi, maxSize)`.
* Allocate a C-owned entry array.
* Copy each entry’s scalar fields.
* Deep-copy each `Entry.Data` into C-owned `raft_bytes_t`.
* Preserve nil-vs-empty byte semantics:

  * nil Go `[]byte` -> `data=NULL`, `len=0`, `is_nil=true`
  * empty but non-nil Go `[]byte{}` -> `data=NULL`, `len=0`, `is_nil=false`
  * non-empty -> C malloc + memcpy, `is_nil=false`
* Return the C-owned array through the callback output.
* C must free it with the repository’s matching `raft_entry_array_free` or equivalent.
* Do not return Go slice backing pointers to C.
* Do not store Go pointers in C structs.

`Snapshot`:

* Call Go `Storage.Snapshot()`.
* Convert metadata:

  * index
  * term
  * ConfState
* Deep-copy `Snapshot.Data` into C-owned memory.
* Preserve nil-vs-empty data semantics.
* Treat this as a large-object path.
* Avoid repeated copies inside the bridge.
* Do not store Go `Snapshot.Data` pointers in C.
* Do not replace etcd’s existing snapshot transport strategy in this phase.
* Document that this compatibility bridge may copy large Snapshot.Data once into C-owned memory, and later phases may consider out-of-band/streaming optimizations without breaking Go Ready/MsgSnap compatibility.

Memory allocation requirements:

Use the repository’s existing C allocation helpers if present.

If helper functions do not exist yet, add minimal safe helpers for:

* copying Go bytes into `raft_bytes_t`,
* freeing `raft_bytes_t`,
* freeing entry arrays,
* freeing snapshot contents,
* freeing ConfState arrays.

Avoid double-free and partial allocation leaks.

For every allocation path, handle failure:

* free any partially allocated C memory,
* set output to empty/zero state,
* return `RAFT_ERR_OUT_OF_MEMORY`.

Cgo pointer-safety requirements:

Forbidden:

* storing raw Go pointers in C,
* storing Go slice data pointers in C-owned structs for later use,
* passing Go-allocated C structs that contain Go pointers into C,
* returning C structs that contain Go pointers,
* retaining borrowed Go memory past the callback.

Allowed:

* passing `uintptr_t(cgo.Handle)` as an opaque handle,
* C calling exported Go bridge functions,
* Go bridge allocating C memory and copying results into it,
* C retaining only C-owned memory after callback returns.

Integration with `NewRawNode`:

The C-backed `NewRawNode` must:

1. validate `Config.Storage` is non-nil, as Go does,
2. create the storage bridge handle,
3. initialize `raft_storage_ops_t` through the C helper,
4. pass the ops into `C.raft_raw_node_new`,
5. store the handle in the Go `RawNode`,
6. on failure, delete the handle and free any temporary C config resources.

If `raft_raw_node_new` copies the `raft_storage_ops_t`, document that. If it stores a pointer to caller-owned ops, fix it so C RawNode copies the ops table internally.

Documentation updates:

Update relevant docs/results to state:

* `Storage` is a Go app-provided interface instance.
* C sees it only as `raft_storage_ops_t + uintptr_t handle`.
* The handle is a `cgo.Handle`, not a raw Go pointer.
* `Entries` and `Snapshot` are large/pointer-bearing paths and must deep-copy into C-owned memory.
* `Term`, `FirstIndex`, and `LastIndex` are scalar paths.
* `InitialState` copies HardState and ConfState.
* callback panics are caught and converted to C error codes.
* storage errors are mapped precisely.
* Storage callback bridge is necessary for Go/etcd compatibility, while C-only users may later use C `MemoryStorage`.
* The bridge does not change etcd’s existing snapshot transport strategy, but it may temporarily add a C-owned Snapshot.Data copy at the RawNode boundary.
