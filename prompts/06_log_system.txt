Goal:

Implement the C internal log subsystem corresponding to Go `raftLog`, `unstable`, and the Storage-backed log access layer.

This phase should make the C core capable of:

* initializing a log from `raft_storage_ops_t`,
* reading terms and entries from unstable or Storage,
* appending unstable entries,
* tracking committed/applied/applying/stable progress,
* producing unstable entries and committed entries for Ready,
* accepting Ready bookkeeping,
* handling snapshots at the log/unstable boundary,
* preserving Go v3.7.0 error semantics for compacted/unavailable/snapshot-unavailable cases.

Do not implement the full raft consensus state machine in this phase unless a small directly related helper is required for tests. Focus on the log subsystem.

Conceptual target:

```text
C raftLog
  -> unstable log/snapshot region
  -> storage-backed stable log region through raft_storage_ops_t
  -> committed / applying / applied indexes
  -> helpers used later by raft core and RawNode Ready/Advance
```

Ownership:

* `unstable.entries` must own its entry array and each entry’s data.
* `unstable.snapshot` must own snapshot data and metadata arrays.
* Storage-backed entries returned by `raft_storage_ops_t.entries` are C-owned callback outputs and must be freed after copying or consuming according to ownership design.
* Do not store Go memory pointers anywhere in `raftLog` or `unstable`.
* All retained entries/snapshots must be C-owned deep copies or ownership-transferred C objects.

Important requirements:

* `maybeTerm(i)` must check unstable snapshot metadata and unstable entries.
* `stableTo(index, term)` must only advance unstable offset when index/term match.
* `stableSnapTo(index)` must clear the unstable snapshot only when index matches.
* `restore(snapshot)` must replace unstable state consistently with the snapshot metadata.
* `truncateAndAppend` must handle:

  * append directly after current unstable end,
  * replace all unstable entries,
  * truncate suffix and append.
* Empty slices/arrays must be represented safely.
* Entry data ownership must be clear and leak-free.

Storage-backed access requirements:

`raft_log_term`, `raft_log_slice`, `raft_log_first_index`, `raft_log_last_index`, and snapshot-related helpers must correctly combine:

```text
unstable state
+
storage-backed stable state
```

Semantics:

* Prefer unstable data when index lies in unstable range.
* Fall back to storage callbacks when index lies in stable range.
* Respect snapshot metadata for terms at snapshot index.
* Correctly propagate storage errors:

  * compacted
  * unavailable
  * snapshot temporarily unavailable
  * out of bounds / invalid argument
* Preserve Go behavior for `zeroTermOnErrCompacted`.

Do not call Go Storage per entry. Keep storage `Entries(lo, hi, maxSize)` batched.

Committed/applied/applying requirements:

Preserve Go v3.7.0 semantics for:

* `committed`
* `applying`
* `applied`

Requirements:

* `commitTo(tocommit)` must never decrease committed.
* `commitTo(tocommit)` must panic/assert/fatal-equivalent if committing beyond last index, matching Go behavior policy.
* `appliedTo(i)` must never move applied backward and must reject applying beyond committed.
* `acceptApplying(index, size, allowUnstable)` must follow Go semantics and interact correctly with `applying`.
* `nextCommittedEnts(allowUnstable)` must return entries after applied/applying up to committed according to Go semantics.
* `hasNextCommittedEnts(allowUnstable)` must match Go readiness behavior.
* `allowUnstable` corresponds to RawNode’s internal `applyUnstableEntries = !asyncStorageWrites`.
* Do not expose `applyUnstableEntries` as a public API.

Ready/Advance integration requirements:

This phase should prepare the log subsystem for existing/future C RawNode Ready/Advance implementation.

Ensure C log provides the primitives needed by:

* `raft_raw_node_has_ready`
* `raft_raw_node_ready`
* `raft_raw_node_ready_without_accept`, if present
* `raft_raw_node_accept_ready`, if present
* `raft_raw_node_advance`

Specifically:

* unstable entries must be obtainable for `Ready.Entries`.
* committed entries must be obtainable for `Ready.CommittedEntries`.
* unstable snapshot must be obtainable for `Ready.Snapshot`.
* after Ready is accepted, unstable entries/snapshot must be marked in progress as Go does.
* after Advance/stable notification, `stableTo` and `stableSnapTo` must clear stable unstable state.
* Do not require passing Go `Ready` back into C for `Advance`.

Snapshot requirements:

Implement log/unstable snapshot semantics:

* restore from snapshot,
* term lookup at snapshot index,
* first index and last index behavior with snapshot,
* stable snapshot clearing,
* storage snapshot fallback,
* snapshot metadata ConfState ownership.

Do not implement etcd snapshot transport. This phase is only log/snapshot metadata and C-owned snapshot object handling inside raft log.

Entry size / max size requirements:

Port Go v3.7.0 entry size limiting behavior used by:

* `Entries(lo, hi, maxSize)`
* `slice`
* `limitSize`
* committed entry batching
* max applying entries size, if present.

If the exact protobuf encoded size helper is not yet available in C, implement a documented skeleton approximation only if necessary, and mark it clearly as a correctness/performance gap. Prefer implementing the actual size calculation only if the repository already has raftpb encoding helpers.

Error and fatal policy:

Follow `ERROR_MAPPING_FOR_C_PORT.md`.

For internal Go panics in log code, use the repository’s C policy:

* assert in internal tests,
* return `RAFT_ERR_FATAL` for recoverable API boundary failures,
* or use the existing skeleton fatal/error convention.

Do not silently ignore invariant violations.

Important invariants to enforce:

* `applied <= applying <= committed <= lastIndex`
* unstable offset is consistent with unstable entries
* snapshot index/term and first index behavior are consistent
* no retained Go pointers
* committed entries returned are ordered and contiguous
* appending conflicting entries truncates the unstable suffix correctly
* storage compacted/unavailable errors are not collapsed incorrectly.
